# ADR 0002: 分類の完全 ONNX 経路を先に検証し、検出の失敗ゲートを継続する

- 日付: 2026-10-24 JST。
- 状態: P1a の限定的な実装判断として採用。P1 全体と製品エンジンの選定は継続。
- 前提: [ADR 0001](0001-onnx-first.md)、[PRODUCT](../PRODUCT.md)、[検証ゲート](../VERIFICATION.md)。必須要件の変更はない。

## 背景

ユーザーが PR #2 をマージし、実装開始を指示した。ブラウザ学習、完全 ONNX のローカル生成、追加変換のない Python 推論を早期に実証する必要がある。一方、D-FINE の既定の bilinear sampling に関係する jax-js ONNX GridSample に、入力範囲内の境界付近で値と勾配の不一致を確認した。

[失敗 probe](../verification/2026-10-24-dfine-probe.md) は演算レベルの証拠であり、D-FINE 全体を移植・評価した結果ではない。この状態で検出学習が成立したとは扱えない。

## 選択

MobileNetV4 Conv Small の公開完全モデルを固定し、ONNX Runtime Web の WASM で凍結特徴を抽出する。新しい線形分類ヘッドの損失を jax-js で自動微分し、SGD で実更新する。ブラウザのモデル固有 exporter で古い分類器を削除し、必要な固定グラフと更新した W / b を単一 FP32 ONNX にまとめる。

新しい ORT Web session と Python CPU で、保存した公開入力の出力が一致することを確認する。更新したヘッドだけを出力する方式は採らない。ユーザーデータはローカル処理し、Python は開発用公開モデル準備と独立推論検証に限る。

P1a は2〜8クラス、画像合計64枚、224×224、固定バックボーン、単一スレッド WASM の範囲とする。元モデルの bicubic / center crop と異なる full-image bilinear stretch を明示し、上流精度を本レシピの性能として使わない。これは検証しやすい前処理を固定する判断で、最終品質プリセットの決定ではない。

## 比較した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 分類と検出を一度に学習可能な汎用 ONNX engine として実装 | 未検証の演算・学習グラフの問題を一括で抱える。現在の成功範囲を説明できない |
| 分類の全バックボーンも初回から再実装 | 将来の選択肢。まず更新した重みを完全 ONNX に反映できる経路を確立する |
| TFJS で分類と検出の training graph を個別実装 | 検出 probe 修正後の結果と比較する候補。現段階で移植コストや同等性は未検証 |
| ORT 固定特徴 + jax-js 分類ヘッド | 今回選択。学習範囲を限定して実更新、完全出力、独立推論を実測できる |

## 成立したことと未成立のこと

分類の既知勾配、損失低下、完全 ONNX、独立 browser / Python 比較は [実測記録](../verification/2026-10-24-browser-classification.md) に残した。画像読込から出力までのサブパス配信と、crossOriginIsolated=false の動作も確認した。

D-FINE の学習、事前学習済み位置推定重みの更新、実データ品質、WebGPU、対象 PC の資源量、checkpoint 保存・再開は未成立または未実施。P1a の分類ヘッド学習を、それらの代わりの完了条件にしない。サンプル正解率は製品品質の証拠にしない。

## 次に判断すること

1. GridSample の期待値・特徴側/座標側勾配を元実装と揃える修正または代替実装。
2. 完全な D-FINE training forward、matching、分類/位置/補助損失の対応と、更新対象パラメータの固定。
3. 同一条件の PyTorch 学習比較、独自クラスの未使用データ評価。
4. 実機・WebGPU・メモリ・保存再開の結果に基づく engine / model の製品採用。

変更は次の PR に記録し、マージはユーザーが行う。

# ADR 0004: 追加調査を復元メモとして保存し、最小再現から再開する

- 記録日: 2026-10-25 JST。
- 状態: 復旧・記録方針を採用。D-FINE の製品採用は保留、G1 は FAIL。
- 比較元: PR #4 のマージ `4549114d40491f16bba75da5742f7c3d3b4e1e77`。
- 前の判断: [ADR 0003](0003-dfine-foundation.md)。

## 背景

PR #4 後に、事前固定した6入力、各 runtime 自身の prefix、最終ヘッドの勾配・更新の比較を追加調査した。会話に残る実行記録では、候補の数値契約は全件不合格で、矩形は最終出力にも差があった。

その追加コード・生レポート・ローカルコミットを GitHub へ保存する前に、作業環境の自動整理で失った。GitHub の保存済み履歴とファイル保管先を確認したが、追加作業は回収できなかった。PR #4 までのコードは GitHub から再取得できた。原因は利用者による削除ではない。

## 判断

1. 会話に残る観測・入力仕様・失敗・レビュー指摘を[復元メモ](../verification/2026-10-24-dfine-prefix-investigation.md)として直ちに保存する。
2. このメモは現在の再実行可能な数値証拠ではない。元の G1、ONNX、商用条件、ブラウザ内処理、実際の検出器学習という要件を変更しない。候補契約を合格・採用済みにしない。
3. 次のコード変更は矩形1画像の元 PyTorch / ORT の不一致を再現する最小ケースに絞り、専用ブランチと draft PR へ保存する。encoder で差が生じ始める箇所を確認し、具体的な修正へ進む。
4. 追加6入力は既知の回帰入力として扱い、再び未使用入力と呼ばない。観測値に合わせた許容差変更で不合格を解消しない。
5. 調査を小さな保存単位に分け、節目と作業停止前に GitHub 上の SHA を確認する。ユーザーがマージする運用は維持する。

## 今回の PR の範囲

現在の状態、追加調査の復元メモ、再開方針、保存手順を更新する文書のみの PR とする。アプリ、モデル、学習処理、依存、CI、公開画面は変更しない。存在しない検証スクリプトを実行可能なコマンドとして案内しない。

過去の部分成功は次の調査の参考であり、追加コードの完成・新しい CI の成功・製品対応の証拠として報告しない。
